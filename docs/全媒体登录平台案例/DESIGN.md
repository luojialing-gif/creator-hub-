# DESIGN.md — 全媒体登录平台 · AI 案例

## 一、全局视觉约定

### ① 画布与安全区
- 画布 1280×720
- padding：上下 60px / 左右 60px
- 内容区 1160×600
- 页尾（页码 + 眉标）：顶边 y=670，左端 x=60、右端 x=1220，字号 14px；**封面不加页尾**（共 9 页，页码 02–09）

### ② 配色方案（抹茶雾绿）

| 槽位 | Hex | 用途 |
|---|---|---|
| 主色 | `#5E7A56` | 大色块、编号块、主标题强调、流程节点 |
| 辅色 | `#A9C19D` | 卡片底、细线、第二层结构 |
| 强调色 | `#C2703D` | 仅用于关键数字与「不做」标记，全篇 ≤ 10% |
| 底色 | `#EEF5EA` | 页面主背景 |
| 浅底卡 | `#F7FBF4` | 卡片底（需 1px `#D9E6D0` 描边） |
| 深色块 | `#3B4A37` | 每页至多 1 块，装最重的信息 |
| 正文 | `#2F3A2C` | 主文字 |
| muted | `#6B7A66` | 说明、注释、页脚 |

色彩纪律：主色 ≤60%、辅色 ≤30%、强调色 ≤10%；禁用阴影；一页最多 2-3 个浅底容器。

### ③ 字体系统
- 中文：`Heiti SC`（黑体-简）
- 西文 / 数字：`Helvetica Neue`
- 字号阶梯：封面主标 72 / 巨型数据 96 / 章节大字 56 / 页面主标 36 / 卡片小标 24 / 正文 18 / 注释 14
- 数字只做巨型锚点时用 Helvetica Neue，句中数字跟随中文

### ④ 视觉母题
**页面主标题 + 其下 1px 贯通细线（`#D9E6D0`，宽 1160）**，所有 content 页复用；页尾右侧为「全媒体登录平台 · AI 案例」小字，左侧为页码。

### ⑤ 配图清单
无位图。全篇用 Box 构图 + 字符箭头（→）表达结构，横平竖直，不混用插画与摄影。

## 二、逐页设计（9 页）

### P1 · 封面
- type: cover | role: hero | rhythm: peak
- layout: 大字报式（b）—— 超大字左对齐，右下角一块主色方块作视觉压角
- visual: 无位图；纯字体 + 一块主色几何
- visual_role: anchor
- density: 字数约 22 / 图片 0 / 留白约 55%
- anti_pattern: 禁止底部数据条；禁止在封面放「83%」等数据；禁止四角装饰
- description: 主标题「全媒体登录平台」（72px），副标「一个人 · 五个平台 · 十几个账号」，底部信息层「AI 案例 · 2026」。右下角 200×200 主色圆角块，块内竖排「CASE」小字。

### P2 · 痛点：账号越多，浏览器越多
- type: content | role: supporting | rhythm: valley
- layout: 左标题色块 + 右内容（m）
- visual: 左侧 30% 主色块，右侧 4 行时间条目（拉高至与色块齐平，不再挂底部结论条）
- visual_role: evidence
- density: 字数约 120 / 图片 0 / 留白约 18%
- anti_pattern: 禁止用等宽四卡片；禁止把耗时做成饼图
- description: 标题「当你负责 2 个及以上账号时：账号的增加等于浏览器的增加」；左侧主色块写「固定开销」+ 大数字 14 分钟 + 副注「一轮开工的固定开销，还没算写稿和剪辑」；右侧四行：打开五个后台 4min / 三个号重新扫码 3min / 找发布入口 2min / 发布前发现掉登录 5min。

### P3 · 起点：第一段需求的关键词
- type: content | role: supporting | rhythm: valley
- layout: **无标题版式**（整页直接进表）—— 左数字色块 + 右七行关键词表
- visual: 左侧主色块承载「需求原文 / 1788 字」，右侧 7 行细线分隔，三栏对齐：编号 / 段落名 / 关键词
- visual_role: evidence
- density: 字数约 110 / 图片 0 / 留白约 12%
- anti_pattern: 禁止把需求原文整段贴成正文；禁止超过 7 行；禁止再加页标题（会让七行挤压）
- description: 全页无标题、无分隔线，内容自顶边 45 起铺满到 495；左侧方块只留「需求原文」+ 大数字 1788 字，整组垂直居中；右侧七行（行高 85px）：01 目标 四后台→一界面·每平台≥3 号 / 02 平台 抖音·小红书·视频号·快手，各带入口 / 03 账号 增删改·六个字段·本地 JSON 导入导出 / 04 登录态 独立 session·一号一实例·重启仍在 / 05 功能 搜索·添加·导入导出·卡片可编辑 / 06 边界 不存密码·不传 Cookie·不绕风控 / 07 验收 四分组·三点开·iframe 失败要提示。

### P4 · 为什么旧办法不行
- type: content | role: supporting | rhythm: valley
- layout: 对比式（h）—— 左「以前试过的」vs 右「都不行的原因」
- visual: 两列，中线分隔，高度对齐
- visual_role: evidence
- density: 字数约 130 / 图片 0 / 留白约 18%
- anti_pattern: 禁止 50:50 对半分；禁止用表格直接贴
- description: 左列三条：浏览器多标签 / 多浏览器多用户 / 网页聚合页；右列对应三条：同平台只能登一个号，登第二个顶掉 / 每次换窗口重找位置，且不告诉哪个掉了 / 四个平台后台都禁止被 iframe 嵌。底部一条结论：三条路都卡在「隔离」和「提醒」上。

### P5 · 做成了什么
- type: content | role: supporting | rhythm: valley
- layout: 左图右文（a）6:4 —— 左 60% 用 Box 模拟软件界面（左栏平台 + 三张账号卡），右 40% 三条说明
- visual: 界面示意（Box 构图，非位图）
- visual_role: anchor
- density: 字数约 120 / 图片 0 / 留白约 15%
- anti_pattern: 禁止把界面示意画成九宫格；禁止右侧超过三条
- description: 左侧模拟界面：深绿左栏（抖音/小红书/微博/视频号/快手）+ 三张账号卡（含「登录态正常」绿点与一张「疑似需重登」橙点）；右侧三条：一窗聚合五个平台 / 每账号独立登录态 / 后台每 4~6 小时静默保活。

### P6 · 关键数字
- type: content | role: hero | rhythm: peak
- layout: 巨型数字 + 洞察（a）
- visual: 96px 数字两组 + 一条对比线
- visual_role: anchor
- density: 字数约 30 / 图片 0 / 留白约 55%
- anti_pattern: 禁止把两个数字放进同一张卡片；禁止加第三个数字稀释
- description: 左「60s → 10s」并排今昔对比；右巨型「83%」+「时间省掉，效率约 6 倍」+「每天省 17 分钟 · 每月省 6.1 小时」；底部一行小字口径：日均进出 20 次，每月按 22 个工作日计。（已去掉底部结论条，整组垂直居中）

### P7 · 搭建工作流
- type: content | role: supporting | rhythm: valley
- layout: 流程链（g）—— 6 个节点横排，箭头连接，下方一条输出条
- visual: 6 个圆角节点 + → 箭头
- visual_role: evidence
- density: 字数约 130 / 图片 0 / 留白约 20%
- anti_pattern: 禁止节点做成等宽卡片网格；禁止画成环
- description: 场景拆解 → 路线选型 → 数据层 → 会话隔离与守护 → 界面交互 → 测试与分发；下方输出条：一个可在 Win/Mac 直接安装的本地工具。

### P8 · 权限边界
- type: content | role: supporting | rhythm: valley
- layout: 对比式（h）—— 左「会做的」深色块，右「不做的」浅底 + 强调色叉
- visual: 左右高度对齐，右侧每条前置「×」
- visual_role: evidence
- density: 字数约 160 / 图片 0 / 留白约 12%
- anti_pattern: 禁止把边界写成免责声明长段落；禁止只写「不做」不写「会做」
- description: 左四条会做：隔离登录态 / 聚合入口 / 定时保活 / 巡检提醒。右四条不做：不代操作不自动发布 / 不读写导出 Cookie 密码 / 不调平台接口不绕风控 / 数据不出本机。底部一条：登录态能保多久由平台决定，工具只提供条件与提醒。

### P9 · 谁能套用
- type: content | role: supporting | rhythm: valley
- layout: 三栏非均分（c）—— 5:3:2，主栏放判断标准，两副栏放岗位
- visual: 主栏深色大字判断句，副栏四个岗位小块
- visual_role: evidence
- density: 字数约 110 / 图片 0 / 留白约 18%
- anti_pattern: 禁止做成四宫格等分；禁止画组织架构图
- description: 主栏一句大字「多系统 × 多账号 × 反复登录 × 入口分散 —— 命中就成立」；副栏列：多店运营 / 客服社群 / 投放优化 / 财务对账。
