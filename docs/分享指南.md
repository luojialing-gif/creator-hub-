# 把 CreatorHub 分享给朋友

> 本文假设朋友只想要「双击能用」的成品。**先说安全**：本工具不保存任何平台密码，
> 账号数据存在各自电脑本机（`~/Library/Application Support/CreatorHub/` 或 Windows 的 `%APPDATA%/CreatorHub/`），
> 打包出来的安装包里**不含**你自己的账号、Cookie 或登录态，可以直接放心发出去。

---

## 一、选哪条路？

| 方式 | 适用 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. GitHub Actions 打全平台安装包**（推荐） | 朋友是 Mac 或 Windows，或你不确定 | 一次出齐：mac arm64/x64 dmg + Windows 安装包/便携版 | 需要一个 GitHub 账号，约 10 分钟 |
| **B. 直接发 macOS 的 .app 压缩包** | 朋友确定是 Mac | 最快，5 分钟搞定 | 只能在 Mac 上用；对方要走一步「解锁」才能打开 |
| **C. 发网页版** | 朋友用手机，或不想装东西 | 谁都能用，发个链接就行 | 做不到多账号登录态隔离（见 README 第六节） |

---

## 二、方式 A：用 GitHub Actions 打全平台安装包

项目里已经配好了 `.github/workflows/build.yml`，内容是：Mac runner 打 dmg，Windows runner 打 exe，
两边都是**手动触发、不签名、不公证**。跟着下面做即可。

### 1. 创建 GitHub 仓库并推送代码

在 [github.com/new](https://github.com/new) 新建一个空仓库（勾选 Public 或 Private 都行，别勾 README），
然后在项目目录里执行：

```bash
cd /path/to/creator-hub
git init
git add -A
git commit -m "CreatorHub 1.1.0"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 首次 push 会要求登录，用 GitHub 用户名 + **Personal Access Token**（不是账户密码）。
> 生成入口：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens，
> 只给这一个仓库的 `Contents: Read and write` 权限即可。

**推送前确认一下**（这一步别跳过）：

```bash
git status --short          # 干净才有下一步
git ls-files | grep -i accounts    # 不应该有任何输出（账号数据不能上云）
```

`.gitignore` 里已经排除了 `node_modules/`、`dist/`、`release/`、`accounts.json`、
以及本机登录态分区目录，**但保留了打包图标**（`build/icon.icns`、`build/icon.ico`）——
缺了图标云端会打包失败。

### 2. 触发打包

打开仓库页面 → **Actions** 标签 → 左侧选 **build** → 右上角 **Run workflow** →
`target` 选 **both** → 绿色按钮确认。

两个 job 并行跑，各 5–10 分钟。跑完在 **Summary** 页面底部 **Artifacts** 区下载：

| Artifact | 内容 | 发给谁 |
| --- | --- | --- |
| `creatorhub-macos` | `CreatorHub-1.1.0-arm64.dmg`、`CreatorHub-1.1.0-x64.dmg` | Apple 芯片 Mac 用 arm64；Intel Mac 用 x64；不确定就都发，错的那个装不上而已 |
| `creatorhub-windows` | `CreatorHub-Setup-1.1.0-x64.exe`、`CreatorHub-Portable-1.1.0.exe` | Windows 用户：正常安装用 Setup；不想装就用 Portable |

> Artifact 默认保留 14 天，记得及时下载转发。

## 三、方式 B：只给 Mac 用户（最快）

```bash
npm run build:app          # 产出 dist/CreatorHub.app
cd dist && zip -qry CreatorHub-mac.zip CreatorHub.app
```

把 `CreatorHub-mac.zip` 发给朋友，附下面的「朋友怎么装·Mac」说明就行。

> zip 会连带 `Contents/MacOS/CreatorHub` 的执行权限一起打包，解压后不用再 `chmod +x`。

## 四、朋友怎么装（直接转给他看）

### Mac

1. 双击下载的 **`.dmg`**（或解压上面的 zip）
2. 把 CreatorHub 图标**拖进 Applications 文件夹**
3. 第一次打开大概率会看到系统拦一下，因为**没有 Apple 开发者签名**（这是刻意的选择，不想花钱买证书、也不想被公证流程卡住）：
   * 弹窗说「无法打开，因为它来自身份不明的开发者」→ 打开 **系统设置 → 隐私与安全性**，
     往下找到「CreatorHub 已被阻止…」，点 **仍要打开**
   * 或者右键 App 图标 → **打开**，同样允许一次
   * 还不行就在终端执行（一行，去掉 quarantine 标记）：
     ```bash
     xattr -cr /Applications/CreatorHub.app
     ```
4. 之后双击就正常了，不再提示。

### Windows

1. 双击 **`CreatorHub-Setup-1.1.0-x64.exe`**，一路下一步（默认装在用户目录，不需要管理员权限）
2. SmartScreen 可能会蓝色弹窗「Windows 已保护你的电脑」→ 点 **更多信息** → **仍要运行**
3. 装好后桌面和开始菜单都有 **CreatorHub** 快捷方式
4. 不想安装就用 **`CreatorHub-Portable-1.1.0.exe`**，双击直接跑，卸载就是删掉那个文件

> 也不签名。企业域控机器如果被策略拦，改用便携版通常可以绕过安装限制。

## 五、朋友第一次用（转给他）

1. 打开 CreatorHub。如果还一个账号都没有，界面中间会有个 **「快速创建 3×4 个账号位」** 按钮，
   会一次性建好 12 个占位账号（抖音 / 小红书 / 视频号 / 快手 各 3 个），先把位置占住再改名就行。
2. 每个账号卡片点 **打开工作台** → 在弹出区域里扫码登录
3. 换账号直接点另一张卡，两个号**互不干扰**（各自独立的登录态分区）
4. 顶部 **巡检登录态** 可以一次性检查所有账号有没有掉线，卡片上会显示「正常 / 疑似失效」

他自己的账号数据只存在他自己电脑上，你可以这样告诉他：

> 卸载 App 不会自动清掉登录数据（这是刻意的，重装后不用重新登录）。
> 想彻底清除：Mac 删 `~/Library/Application Support/CreatorHub/`，
> Windows 删 `%APPDATA%\CreatorHub\`。

## 六、常见问题

**Q：朋友更新版本，登录态会没吗？**
A：不会。登录数据在系统数据目录里，覆盖安装不影响。

**Q：为什么不做副署签名？**
A：Mac 开发者签名 99 美元/年，Windows 代码签名证书更贵。朋友自用走「仍要打开」就能搞定，
愿意付费签名的话，把证书配到 Actions 里替换 `CSC_IDENTITY_AUTO_DISCOVERY: 'false'` 那一行即可。

**Q：可以放到公开仓库吗？**
A：可以。代码里没有任何你的个人信息 —— 账号数据不入库，`README.md` 里也没有敏感内容。

**Q：构建失败了怎么看？**
A：Actions 页面点进失败的 job 看日志。最常见两个原因：
① 忘了提交 `build/icon.icns` 或 `build/icon.ico`；
② `git rm -r --cached build` 之后没重新 `git add`（用 `git ls-files build/` 确认图标在库里）。
