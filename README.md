# CreatorHub · 多平台创作者中心聚合工作台

把**抖音 / 小红书 / 视频号 / 快手**四个创作者后台聚合到一个界面里，每个平台支持任意多个账号，
**每个账号一份独立且持久化的登录态**，重启应用后不用重新登录。

---

## 一、先说结论：能不能做到「多账号独立登录态」

| 方案 | 能否隔离第三方登录态 | 说明 |
| --- | --- | --- |
| **Electron 桌面版（本项目主方案）** | ✅ 能 | 每个账号绑定一个独立的 `persist:` 分区，Cookie / localStorage / IndexedDB 各存各的、各落各的盘，重启应用自动还原 |
| 纯网页版（本项目附带） | ❌ 不能 | 浏览器里同一域名的 Cookie 是共享的，网页无权隔离；已退化为「账号导航聚合页」 |
| 网页 iframe 内嵌 | ❌ 不能 | 这四个平台的创作者后台都设置了 `X-Frame-Options` / CSP `frame-ancestors`，iframe 会被拒绝 |

所以主交付物是 **Electron 桌面应用**，另外附一个单文件网页版作为降级方案（见第六节）。

## 三、安装与运行

需要 Node.js ≥ 18（本机已验证 v22）。依赖已装好，Electron 二进制为 33.4.11。

### 推荐：用打包好的 CreatorHub.app（双击即用）

**为什么推荐它**：不依赖 Terminal。macOS 上双击 `.command` 要经由 Terminal 去执行，
在装了端点安全软件 / 策略管控的机器上这条链路常被拦掉，表现为「双击毫无反应」。
`.app` 走的是 LaunchServices，直接拉起进程，绕开整个问题。

```bash
npm run build:app            # 生成 dist/CreatorHub.app（约 234MB，自带图标、已 ad-hoc 签名）
./安装到桌面.command          # 把它装到桌面（也可 ./安装到桌面.command /Applications）
```

也可以在访达里直接把 `dist/CreatorHub.app` 拖到桌面或「应用程序」文件夹。

打包脚本做的事（`tools/build_app.py`）：复制 `Electron.app` → 装入 `src/` →
把主可执行文件与 4 个 Helper 子进程一致改名 → 改写各处 `Info.plist` →
换图标 → 全包重新 ad-hoc 签名 → 清除 quarantine 扩展属性。

> **改名与重签名缺一不可**：只改主程序名不改 Helper，Chromium 找不到子进程；
> 改完不重新签名，Apple Silicon 会直接拒绝启动。

### 备选：命令行启动

```bash
cd creator-hub
npm start            # 启动桌面应用
npm run dev          # 带开发者工具的方式启动
npm run smoke        # 无界面自检：验证「每个账号独立分区」是否真的成立
```

`.command` 启动器仍保留（`启动桌面版.command` / `启动网页版.command`）。
若双击没反应，**改成在「终端」里手动执行**通常可以：

```bash
cd "/Users/Zhuanz/WorkBuddy/2026-10-13-16-39-44/creator-hub"
./启动桌面版.command
```

也可以直接双击 `web/creator-hub-web.html`，效果与 `启动网页版.command` 相同。

### 单实例

应用带单实例锁（`app.requestSingleInstanceLock()`）。重复启动不会开出第二个窗口，
而是把已有窗口唤到前台。这是必要的：两个实例共用同一份 `userData` 与 `Partitions/` 目录，
会争抢分区，并可能各自把内存里的账号列表写回 `accounts.json` 互相覆盖。

> **Electron 二进制下载慢 / 卡住**时，先配国内镜像再装：
> ```bash
> ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/" npm install
> ```
> 安装完成后 `node_modules/electron/dist/` 下应出现 `Electron.app`（macOS）。

`npm run smoke` 会真的创建两个账号、各自建 session、往 A 的 Cookie 罐里写一条探测 Cookie，
断言 B 读不到，最后输出一行 JSON（`{"smoke":"PASS", ...}`）并以退出码表达结果。

## 四、登录态是怎么保持的（核心机制）

```
账号「抖音·主号」  →  session 分区 persist:douyin-account-1
账号「抖音·小号」  →  session 分区 persist:douyin-account-2
账号「小红书·主号」→  session 分区 persist:xhs-account-1
账号「视频号·A」   →  session 分区 persist:wxch-account-1
账号「快手·主号」  →  session 分区 persist:ks-account-1   （实际为 kuaishou-account-1）
```

* 分区名里的 `persist:` 前缀是关键：**没有它，数据只活在内存里，关掉应用就清空**；有它才会写入磁盘。
* 磁盘位置（macOS）：`~/Library/Application Support/CreatorHub/Partitions/<分区名>/`
* 账号编号 `slot` 一旦分配就**不再变化**：改别名、改备注、改 URL、导入导出都不会让它改变 ——
  否则账号会「换一份登录态」。导入时也会保留原 `slot`。
* 每个分区还会把默认 UA 里的 `Electron/x.y.z` 标识去掉（可在设置里关掉）。
  这只改标识，**不绕过任何验证、验证码或风控**。

**应用自身的数据**（账号配置）在：`~/Library/Application Support/CreatorHub/accounts.json`，
每次保存前会自动留一份 `accounts.backup.json`；主文件损坏时自动从备份恢复，不会白屏。

### 登录态守护（`src/session-guard.js`）

`persist:` 分区只解决「隔离」，**掉登录的另一个常见根因**是：平台登录成功后会写入
**会话型 Cookie**（不带过期时间），Chromium 默认不把它落盘，应用一关登录态就丢。
守护模块为此做三件事，且全部可以在「设置 → 登录态守护」里开关：

1. **会话凭据加固**：把不带过期时间的会话型 Cookie 补上一个远期过期时间（值原样不动，
   跳过 `__Host-` 前缀的平台安全 Cookie），让 Chromium 愿意把它写进磁盘。
   登录成功后、周期巡检后、退出应用前都会自动执行。
2. **定期落盘**：每隔一段时间（默认 10 分钟，可改）对所有分区执行 `flushStorageData()`，
   把内存里的 Cookie / localStorage 强制写盘，避免异常退出丢数据。
3. **静默巡检**：定时用不可见视图逐个账号访问平台后台，按登录页特征判断是否被踢回登录页；
   结果只反映在账号卡片的登录态徽标上（正常 / 疑似失效 / 未检测），**绝不自动重新登录**。
   顶部「巡检登录态」按钮可手动触发，批量打开也支持「仅疑似失效」。

守护模块有自动化断言保证它**不读取、不记录、不导出任何 Cookie 的值**，
返回的统计里只有数量（加固了几条），没有内容。

## 五、Electron 版使用说明

**界面结构**：顶部（搜索 / 添加账号 / 导入 / 导出 / 主题 / 设置）→ 左侧平台列表 → 右侧账号卡片。

**账号卡片**提供：打开工作台、新窗口打开、复制链接、编辑、删除、备注、↑↓ 排序（也支持拖动卡片排序）。

* **打开工作台**：在界面内嵌区域打开该平台后台，使用该账号自己的登录态。若显示登录页，直接在里面扫码/登录即可。
* **新窗口**：用独立窗口打开，**同样使用该账号的分区**，适合双屏对照。
* **一键打开…**：批量打开当前平台的全部账号 / 仅「未登录」/ 仅「待发布」/ 仅「疑似失效」；每个账号一个独立窗口，窗口之间错开 0.26 秒逐个加载（避免同瞬间并发被风控）。
* **登录态徽标**：每张账号卡片上显示最近一次巡检结果（正常 / 疑似失效 / 未检测 + 检测时间）；
  顶部「巡检登录态」按钮可随时手动全量巡检。看到「疑似失效」时，用「仅疑似失效」一键只重开那几个号重新扫码即可。
* **设置 → 登录态守护**：可开关「会话凭据加固」「定期落盘」「静默巡检」，并可调整巡检间隔。
* **登录后 URL**：视频号登录后会跳转，导致下次打开又落到登录页。在「编辑账号」里填上登录后的工作台地址，此后打开该账号会直接跳到那里。
* **清理登录态**（编辑账号 → 清理登录态）：只清该账号分区在本机的 Cookie / localStorage / 缓存，等于把它登出，其它账号不受影响。删除账号**不会**顺手清登录态，这是刻意设计的。
* **设置**里可以看到每个账号的分区名与目录、是否已落盘，以及「释放后台视图」（切走的账号默认继续在后台运行，占内存；释放后磁盘登录态不受影响）。
* 快捷键：`⌘K` 聚焦搜索、`⌘R` 刷新当前工作台页面、`⌘⇧L` 返回账号列表、`Esc` 关闭弹层。

## 六、纯网页降级版（`web/creator-hub-web.html`）

双击即可用，零依赖、单文件。它**做不到**隔离第三方登录态，所以只做「账号导航聚合」：

* 点击账号 → **新标签**打开对应平台后台；账号别名/备注/URL/排序/状态存在 `localStorage`。
* 首屏有一条明确的黄色提示条说明这个限制（可在设置里关掉）。
* 「尝试内嵌」按钮保留，但**默认不自动内嵌**。8 秒内没有收到加载事件就判定被拒，
  显示提示：**「该平台禁止嵌入，请点击新标签打开」**，并提供「新标签打开 / 复制链接 / 收起内嵌」，不会白屏。
  收到加载事件但页面空白，同样会提示这是平台策略而不是故障。
* 支持搜索、增删改、拖动/按钮排序、导入导出 JSON、深色模式、响应式（手机可用）。
* **要真正做到多账号隔离，请配合浏览器自带方案**：
  * **Chrome**：右上角头像 → 「添加」个人资料，每个资料开一个窗口，登录态互相独立；
  * **Edge**：用「工作区」，或同样开多个个人资料；
  * **Firefox**：装 Multi-Account Containers，用「容器标签」在同一窗口里按容器隔离登录态。

本页只负责把这些账号集中成一张卡片列表，点一下就到对应后台。

## 七、安全边界（本工具的明确承诺）

* ❌ 不保存任何第三方平台账号密码。
* ❌ 不读取、不导出、不上传、不共享第三方 Cookie —— 导出 JSON 里只有别名/备注/URL/排序/状态，**没有 `slot` 之外的任何域信息，更没有 cookie 字段**（有自动化断言）。
* ❌ 不绕过平台登录、验证码、风控；不做自动登录、不模拟点击验证。
* ✅ 登录态能维持多久，由平台决定（平台主动过期、异地登录顶号、风控要求重新验证，本工具都无能为力）。
  本工具只负责**尽量持久化本地会话**，不做任何对抗。
* ⚠️ 内嵌视图里访问的是真实平台页面，平台可能检测到浏览器环境与设备指纹。若某个平台要求更严格的环境，请改用系统浏览器配合多用户方案。

### 「一个月不掉线」——哪些可控、哪些不可控

**本工具能控制的（已做，且有自动化验证）：**

* 每个账号独立 `persist:` 分区，多账号互不串登录态（5 个、10 个都一样）；
* 会话型 Cookie 加固为可落盘 + 定期/退出前强制落盘 —— 解决「重启应用就要重新登录」；
* 静默巡检提前发现「疑似失效」，而不是等你发内容时才发现被登出。

**本工具控制不了的（任何工具都控制不了）：**

* **平台服务端主动让凭据过期**：抖音/小红书等平台会按自己的安全策略让登录态失效，
  这是服务端行为，本地怎么保存都没用；
* **异地/异端登录顶号**：同一个账号在另一台设备登录，本机登录态可能被平台作废；
* **风控要求重新验证**：频繁切换、批量操作触发平台风控时，平台会强制重新扫码；
* **账号自身问题**：封号、限制登录等。

**实际建议**：守护全开后，正常使用下登录态以「周」为单位保持是常见情况；
但「保证一个月」没有任何工具能承诺 —— 能做到的是「掉了第一时间在卡片上看到徽标，
一键只重新打开失效的那几个」。

## 九、验证与测试

仓库自带四套可复跑的检查，建议改代码后依次跑一遍：

```bash
npm run test            # 数据层单元测试（25 项）：分区编号稳定性、排序、导入导出、损坏恢复
npm run test:guard      # 登录态守护单元测试（52 项）：加固、落盘、巡检判定、凭据不泄露断言
npm run test:web        # 网页版冒烟（46 项，jsdom 真跑）：增删改、排序、批量、内嵌降级、重载恢复
npm run verify:static   # 单文件静态检查：零外链、标签配平、id 存在性、渲染函数调用链无环
npm run smoke           # Electron 端到端自检：见下
npm run verify          # 上面四项一次跑完
```

**`npm run smoke` 会真的验证「独立 session」与「登录态可落盘」这两件事**：创建两个同平台账号
→ 分别拿到不同的 `persist:` 分区 → 往 A 的 Cookie 罐写一条探测 Cookie → 断言 B 读不到 →
再写一条**会话型** Cookie（不带过期时间，正是掉登录的根因）→ 跑守护加固 →
断言它拿到远期过期时间且**值原样未动** → 断言守护返回的统计里不含任何凭据内容 →
断言导出内容里没有任何凭据字段。自检跑在隔离目录（`…/CreatorHub/smoke-<pid>`），
结束后自动清理，不会碰你真实的账号与登录态。

> ⚠️ `npm run smoke` 请在**你自己的终端**里执行。在受限的沙箱 / 安全策略环境中，
> Chromium 的子进程沙箱可能无法初始化（报 `sandbox initialization failed`），
> 那是环境限制而非应用缺陷；此时 `npm run test` 与 `npm run test:web` 已覆盖绝大部分逻辑。
> 若启动时报 `app.setName is not a function`，说明环境里设了 `ELECTRON_RUN_AS_NODE=1`，
> 改用 `env -u ELECTRON_RUN_AS_NODE npm start` 即可。

**打包产物的验证**（可对 `dist/CreatorHub.app` 复跑，与开发版同一套断言）：

```bash
CREATORHUB_SMOKE=1 ./dist/CreatorHub.app/Contents/MacOS/CreatorHub    # 期望输出 {"smoke":"PASS", ...}
```

最近一次结果：自检 **17/17 通过**，其中包含关键的两条 ——
**A 账号写入的 Cookie 在 B 分区读不到（`A=1 B=0`）**、
**会话型 Cookie 加固后拿到远期过期时间且值原样保留（`converted=2`）**。
另已验证：`open dist/CreatorHub.app`（等同双击）能正常拉起主进程与 GPU/渲染 Helper；
重复启动时第二个进程打印「已有实例在运行」后退出，实例数保持 1。

> 注意：若你的 shell 里存在 `ELECTRON_RUN_AS_NODE=1`，上面这条命令会退化成 Node REPL（表现为
> 打印 `Welcome to Node.js` 后挂住）。加 `env -u ELECTRON_RUN_AS_NODE` 前缀即可。

## 十、已知限制

1. **内嵌视图始终在最上层**：弹层打开时应用会临时把内嵌视图收起，关闭后自动恢复，属于实现上的取舍。
2. **内存占用**：每个打开的账号是一个真实的 Chromium 渲染进程；切走的账号默认保留在后台（可关掉该设置或手动释放）。
3. **平台改版**：登录入口 URL 与跳转行为会变，账号里可以随时自定义 URL。
4. **纯网页版无法隔离登录态**，这是浏览器同域 Cookie 共享决定的，不是实现缺陷。
5. 在受限沙箱环境里 Electron 可能无法启动（Chromium 子进程沙箱被拒），属环境问题。
6. **`.command` 启动器依赖 Terminal**：macOS 上双击 `.command` 是由 Terminal 去执行的，
   在装有端点安全软件 / 策略管控的机器上这条链路可能被拦，表现为「双击没反应」。
   替代方案：改用 `dist/CreatorHub.app`（走 LaunchServices），或在终端里手动执行脚本。
7. **打包版是 ad-hoc 签名**，不是 Apple 开发者签名。首次打开若被拦，
   在「系统设置 → 隐私与安全性」里点「仍要打开」即可；本机自建的包不带 quarantine 属性，通常不会触发。
8. `smoke` 模式在注册 IPC 之前就返回，渲染层会打一条
   `No handler registered for 'hub:boot'` —— 仅自检路径的噪声，正常启动不受影响
   （正常模式是 `registerIpc()` 先于 `createMainWindow()`）。
